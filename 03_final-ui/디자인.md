# 신한 슈퍼SOL 보험 탭 — 최종 UI 디자인 가이드

> 3단계 **최종 UI(D-1, 8/20~24)**의 기준 문서. 와이어프레임을 실제 UI로 바꿀 때 이 문서대로 한다. 영준·종광·찬영 공용.
> 원칙의 출처: `CLAUDE.md` "디자인 원칙" · 토큰 원본: `00_reference/design-tokens/tokens.md` · 팔레트 결정: `docs/2026-08-17_팔레트-2계열-발견-및-기준-결정.md`(R-01)
> 🔷 표시 = 팀장 결정 필요. 이 문서에서 제안한 기본값으로 진행하되, 바꾸면 여기를 고친다.

## 0. 한 줄 원칙

**룩앤필은 슈퍼SOL 그대로. 우리가 바꾸는 것은 구조·배치·흐름이지 생김새가 아니다.**

왜 이렇게 가는가:
1. **측정 때문.** 9/11 테스트는 기존 앱 vs MVP를 같은 과제로 비교한다. 생김새까지 바꾸면 "예뻐서 이긴 건지 구조가 나아서 이긴 건지" 가를 수 없다. 생김새를 고정해야 구조의 효과만 남는다.
2. **도입 현실성.** 우리 안이 실제로 들어간다면 슈퍼SOL 디자인 시스템 안에서 구현된다. 새 스타일을 만들면 "예쁜 딴 앱"이 된다.
3. **팀 여력.** 디자인 인원 3명 중 2명이 Figma 초보다. 새 스타일을 만들 시간에 구조를 다듬는 게 맞다.

→ 그래서 **색·글자·라운드·버튼·여백은 전부 "찾아서 그대로 쓰는 것"이고, 만드는 것이 아니다.**

## 1. 유지 / 개선 경계

| 그대로 유지 (손대지 않음) | 우리가 바꾸는 것 |
|---|---|
| 색 팔레트 (브랜드 블루 · 그레이 단계 · 배경 · 구분선) | 정보 구조(IA) · 화면 흐름 |
| 버튼 높이·라운드·색 | 요소 배치 · 순서 · 우선순위 · 묶음 |
| 카드 라운드·패딩·테두리 | 상태별(0건/보유) 노출 차이 |
| 폰트 크기 스케일 · 굵기 | 문구 (단, 슈퍼SOL 어조 유지 — "~해요"체) |
| 아이콘 크기 · 여백 단위 | 컴포넌트 **조합** (새 컴포넌트는 기존 토큰으로만) |
| 상태바 · 헤더 · 상단 탭 · 하단 탭바 | 어떤 컴포넌트를 어디에 두느냐 |

**회색 지대 판단 기준:** "이 요소를 슈퍼SOL 다른 탭(은행·카드)에 그대로 옮겨놔도 어색하지 않은가?" — 어색하면 우리가 만든 스타일이니 빼라.

## 2. 기준 팔레트 = SOL 계열 (R-01 결정)

보험 영역 안에 **두 디자인 시스템이 섞여 있다** — 슈퍼SOL 본체(SOL 계열)와 신한라이프 제공 화면(라이프 계열). 우리는 **SOL 계열 하나로 통일**한다.

| | SOL 계열 ✅ 기준 | 라이프 계열 ❌ 쓰지 않음 |
|---|---|---|
| Primary | `#005DF9` | `#265BF0` / `#3668F6` |
| 텍스트 최상위 | `#101828` | `#111726` |
| 본문 | `#344054` | `#495365` |
| 버튼 | h48 · r8 (인라인) | h56 · r16 |
| 해당 화면 | 01 틀 · 02 · 03 · 06 · **07 시작시트·1/5** | 04 · 05 · **07 청구 랜딩** · 01 추천 카드 |

8/23 픽셀 실측: **청구 한 흐름 안에서도** 랜딩(07-1)은 라이프 계열(`#265BF0`·`#111726`), 시작시트(07-2)·1/5(07-3)는 SOL(`#005DF9`·`#101828`)이다. R-01의 추가 근거. 실측 전체: `00_reference/design-tokens/픽셀실측_2026-08-23.txt`

→ **04(타사 목록)·05(자사 상세)를 SOL로 바꾸는 것 자체가 시안의 근거(R-01)다.** 종광의 S6-A가 이미 06 구조로 통일했다.
→ 신한라이프 **로고·이름**은 그대로 쓴다. 바꾸는 건 토큰이지 브랜드 표기가 아니다.

## 4. 타이포그래피

**Figma: `Noto Sans KR`** (Regular · Medium · Bold — Semi Bold 없음). Inter는 한글 글리프가 없어 **절대 금지**. 실제 앱 서체는 신한 전용으로 추정되며 이 환경에 없다.
🔷 **React MVP 폰트**: Pretendard(웹폰트, 신한 서체와 시각적으로 가장 가까움) 제안. Figma와 MVP 서체가 달라지지만 스케일·굵기가 같으면 테스트에 영향 없음.

Figma 텍스트 스타일 13개 — **이미 전 화면에 적용돼 있으므로 최종 UI에서 건드리지 않는다.**

## 6. 컴포넌트 규칙 — 기존 27 + 신규 12

원본은 Figma `🧩 컴포넌트 · 토큰` 페이지 섹션 `9:2`(🔒). **최종 UI에서도 인스턴스를 분리하지 않는다.** 변형이 필요하면 원본에 variant를 추가한다(영준).

| 컴포넌트 | 최종 스펙 | 와이어프레임 → 최종 전환 시 |

### 왜 Lucide가 아니라 Phosphor인가 (실측, 2026-08-23)

캡처 `01_금융-보험홈_a/c`의 아이콘을 픽셀 단위로 재면:
- **SOL 헤더 아이콘 = 획 1.5 @24 · 라운드 캡/조인 · 글리프 20×17이 24 박스 안에** (검색 아이콘 실측: 3x 캡처에서 획 4~5px, 글리프 56×51px)
- **SOL 탭바 아이콘 = 채움(solid)** — 라인이 아님. 즉 실제 앱은 **라인 + 채움 두 스타일을 함께** 쓴다

| 후보 | 획 @24 | 라인+채움 한 세트 | 아이콘 수 | 판정 |
|---|---|---|---|---|
| **Phosphor** (MIT) | **1.5** ✅ | ✅ Regular/Fill 6 weight | 1,512 | **채택** |
| Heroicons | 1.5 ✅ | ✅ | 316 | 보험 서비스 12종을 덮기엔 부족 |
| Lucide | 2.0 ❌ | ❌ 라인만 | ~1,600 | 획이 굵어 탭바·헤더가 실제와 어긋남 |
| Tabler / Remix / Material | 2.0 ❌ | 일부 | — | 동일 |

추가 근거 — Phosphor SVG는 **stroke가 아니라 채움 패스**(viewBox 256, `fill=currentColor`)다. 그래서 ① Figma 색상 **변수를 fill에 그대로 바인딩**할 수 있고(SOL 모드 전환 자동), ② 팀원이 인스턴스를 24→32→44로 키워도 **획 두께가 비율대로 따라온다**. stroke 기반 세트(Lucide·Tabler)는 둘 다 안 된다. Figma 초보 2명이 쓰는 조건에서 이 차이가 크다.

**한계(D-9에 기록):** Phosphor Fill은 실제 SOL 탭바 아이콘보다 모서리가 둥글다. 탭바는 AS-IS·시안이 **동일한 고정 요소**라 9/11 비교에 영향을 주지 않으므로 그대로 간다.

**⚠️ 측정 관련 한계 (D-9에 기록):** AS-IS의 서비스 아이콘 12개는 통일된 세트가 아니라 **초록 지폐·노란 전구·빨간 십자·하늘색 카드가 뒤섞인 컬러 미니 일러스트**다(캡처 `01_금융-보험홈_c`). 이걸 라인 세트 하나로 통일하면 정돈돼 보이는데, 그건 **우리가 주장하는 구조 개선이 아니라 재현 불가에 따른 대체**다. 9/11 테스트에서 "구조가 나아서 이긴 건지 아이콘이 정돈돼서 이긴 건지" 갈리지 않으므로 **교란 변수로 명시**한다. (컬러 일러스트 21개를 새로 만드는 것은 물리적으로 불가능하므로 통일이 유일한 현실적 선택)

### 7-1. 3D 일러스트·캐릭터 자리를 채우는 법 — 🔄 방침 변경 (2026-08-23 팀장 결정)

**바뀐 것:** 이전 방침은 "만들지 않고 아이콘 타일로 마감"이었다. → **플러그인·무료 라이선스 에셋을 최대한 활용해 확보하거나, 없으면 직접 제작한다.**

**그래도 절대 안 되는 것 (이건 안 바뀜)**
- ❌ 캡처 `01_금융-보험홈_a`의 **흰 곰 = 신한 마스코트** — 상표·저작물. 추출도, "비슷하게" 생성도 금지. 유사 생성이 더 나쁘다.
- ❌ 실제 앱의 3D 오브젝트를 모사하는 것. 우리가 채우는 건 **같은 자리에 놓는 우리 에셋**이지 SOL 에셋의 대체품이 아니다.

**⚠️ 플러그인은 실행 못 하지만, 에셋은 넣을 수 있다 (2026-08-23 확인).** MCP로 Figma **플러그인 UI를 클릭하는 것**은 불가능하다. 하지만 오픈 라이선스 세트는 **원본 파일을 받아 `upload_assets`로 직접 넣으면** 플러그인 없이 들어온다 — 아래 18개를 이 방식으로 넣었다. 즉 플러그인이 꼭 필요한 건 **3dicons·Blush처럼 사이트/플러그인으로만 배포하는 세트**뿐이고, 그건 영준이 Figma에서 직접 한다.

- **크기:** 카테고리 아이콘 48~64 / 배너·팝업 96~160.
- **⚠️ 래스터(PNG)다.** 색상 변수 바인딩이 안 되고 SOL 모드 전환에도 안 따라온다. 3D 에셋의 성질이라 정상 — **아이콘 톤을 맞춰야 하는 자리는 Phosphor를 쓴다.**
- **✅ 아이콘 3종 교체 (8/23):** `암` 노란 리본 → **세포** (노란 리본 = **세월호 추모 상징**으로 오독될 위험. 세포는 라인 세트 Phosphor `virus`와 같은 모티프라 일관됨) · `연금저축` 돈주머니 → **주판** (`$` 표시 제거) · `변액` 상승 차트 → **새싹** (격자가 납작해 3D 결이 약했음)
- **⚠️ 색이 오브젝트마다 다르다**(노란 리본·파란 밴드·주황 돈주머니). SOL 블루 단색이 아니다. 다만 **AS-IS도 컬러 미니 일러스트가 뒤섞여 있으므로**(아래 측정 한계 문단) 실물에 더 가깝다.

## 8. 와이어프레임 → 최종 UI 전환 절차 (화면 1장 기준)

1. **`시안` 페이지에서 `최종 UI 디자인` 페이지(`5:4`)로 복제.** 원본은 남긴다(8/25 대조용).
2. **변수 모드 전환** — 프레임 선택 → 우측 패널 레이어 섹션 → `색상` 컬렉션 모드 **와이어프레임 → SOL**. 색이 바인딩된 요소는 전부 자동으로 바뀐다. 안 바뀌는 요소 = 변수 안 쓴 것 → 찾아서 변수 바인딩 (영준에게 요청 가능).
3. **텍스트 스타일 확인** — 이미 적용됨. 바꾸지 않는다.
4. **플레이스홀더 교체** — 아이콘 플레이스홀더 → §7 아이콘 / 이미지 플레이스홀더 → §7 일러스트 방침. 회색 박스가 남아 있으면 안 됨.
5. **회색조 전용 표현 정리** — 점선 슬롯 테두리 제거 · "1st 뷰포트 접힘선" 레이어 숨김 · 노트 프레임은 화면 밖 유지.
6. **상태 표현 색 적용** — §3 상태 색 규칙 (선택/부족·충분/토글).
7. **프레임 이름** — `[아이디어 N]` 태그 유지. "개선안" 글자 금지(8/25 전).
8. **검수 (§10)** → `03_final-ui/figma-links.md`에 노드 ID 기록.

화면 순서: 테스트 과제에 걸린 것부터 — S1(보험료 확인) → S4·S5(청구) → S3(보장) → S2(찾기) → S6.

### #3 아이콘 세트 — Phosphor 확정 (8/23)

한때 §11 기본값에 **Lucide**가 남아 있어 혼선이 있었으나, 같은 날 §7이 실측을 근거로 **Phosphor**를 채택했고 세트도 이미 만들어져 있다. **이미 만들어놓은 것을 쓴다는 팀장 결정에 따라 Phosphor로 확정**하고, Lucide 표기는 폐기한다.

| | Lucide (폐기) | **Phosphor (확정)** |
|---|---|---|
| 획 @24 | 2.0 — SOL 실측 1.5와 어긋남 | **1.5** — 실측 일치 |
| 탭바 채움(solid) | ❌ 라인만 | ✅ Regular/Fill 한 세트 |
| 색 변수 바인딩 | ❌ stroke 기반 | ✅ fill 패스 → 변수 바인딩 O, 확대 시 획 비율 유지 |
| 제작 상태 | 미제작 | **41개 완료** `278:110` + 매핑표 `03_final-ui/아이콘-매핑.md` |

**표에 없는 아이콘이 필요하면 새로 만들지 말고 영준에게 요청** — 다른 세트를 섞으면 §7 실측 근거가 깨진다.
