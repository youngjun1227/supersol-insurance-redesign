# 신한 슈퍼SOL 보험 탭 — 최종 UI 디자인 가이드

> 3단계 **최종 UI(D-1, 8/20~24)**의 기준 문서. 와이어프레임을 실제 UI로 바꿀 때 이 문서대로 한다. 영준·종광·찬영 공용.
> 원칙의 출처: `CLAUDE.md` "디자인 원칙" · 토큰 원본: `00_reference/design-tokens/tokens.md` · 팔레트 결정: `docs/2026-08-17_팔레트-2계열-발견-및-기준-결정.md`(R-01)
> 🔷 표시 = 팀장 결정 필요. 이 문서에서 제안한 기본값으로 진행하되, 바꾸면 여기를 고친다.

## 0. 한 줄 원칙

**룩앤필은 슈퍼SOL 그대로. 우리가 바꾸는 것은 구조·배치·흐름이지 생김새가 아니다.**

왜 이렇게 가는가:
1. **측정 때문.** 9/11 테스트는 기존 앱 vs MVP를 같은 과제로 비교한다. 생김새까지 바꾸면 "예뻐서 이긴 건지 구조가 나아서 이긴 건지" 가를 수 없다. 생김새를 고정해야 구조의 효과만 남는다.
2. **도입 현실성.** 우리 안이 실제로 들어간다면 슈퍼SOL 디자인 시스템 안에서 구현된다. 새 스타일을 만들면 "예쁜 딴 앱"이 된다.
3. **팀 여력.** 디자인 인원 3명 중 2명이 Figma 초보다. 새 스타일을 만들 시간에 구조를 다듬는 게 맞다.

→ 그래서 **색·글자·라운드·버튼·여백은 전부 "찾아서 그대로 쓰는 것"이고, 만드는 것이 아니다.**

## 1. 유지 / 개선 경계

| 그대로 유지 (손대지 않음) | 우리가 바꾸는 것 |
|---|---|
| 색 팔레트 (브랜드 블루 · 그레이 단계 · 배경 · 구분선) | 정보 구조(IA) · 화면 흐름 |
| 버튼 높이·라운드·색 | 요소 배치 · 순서 · 우선순위 · 묶음 |
| 카드 라운드·패딩·테두리 | 상태별(0건/보유) 노출 차이 |
| 폰트 크기 스케일 · 굵기 | 문구 (단, 슈퍼SOL 어조 유지 — "~해요"체) |
| 아이콘 크기 · 여백 단위 | 컴포넌트 **조합** (새 컴포넌트는 기존 토큰으로만) |
| 상태바 · 헤더 · 상단 탭 · 하단 탭바 | 어떤 컴포넌트를 어디에 두느냐 |

**회색 지대 판단 기준:** "이 요소를 슈퍼SOL 다른 탭(은행·카드)에 그대로 옮겨놔도 어색하지 않은가?" — 어색하면 우리가 만든 스타일이니 빼라.

## 2. 기준 팔레트 = SOL 계열 (R-01 결정)

보험 영역 안에 **두 디자인 시스템이 섞여 있다** — 슈퍼SOL 본체(SOL 계열)와 신한라이프 제공 화면(라이프 계열). 우리는 **SOL 계열 하나로 통일**한다.

| | SOL 계열 ✅ 기준 | 라이프 계열 ❌ 쓰지 않음 |
|---|---|---|
| Primary | `#005DF9` | `#265BF0` / `#3668F6` |
| 텍스트 최상위 | `#101828` | `#111726` |
| 본문 | `#344054` | `#495365` |
| 버튼 | h48 · r8 (인라인) | h56 · r16 |
| 해당 화면 | 01 틀 · 02 · 03 · 06 · **07 시작시트·1/5** | 04 · 05 · **07 청구 랜딩** · 01 추천 카드 |

8/23 픽셀 실측: **청구 한 흐름 안에서도** 랜딩(07-1)은 라이프 계열(`#265BF0`·`#111726`), 시작시트(07-2)·1/5(07-3)는 SOL(`#005DF9`·`#101828`)이다. R-01의 추가 근거. 실측 전체: `00_reference/design-tokens/픽셀실측_2026-08-23.txt`

→ **04(타사 목록)·05(자사 상세)를 SOL로 바꾸는 것 자체가 시안의 근거(R-01)다.** 종광의 S6-A가 이미 06 구조로 통일했다.
→ 신한라이프 **로고·이름**은 그대로 쓴다. 바꾸는 건 토큰이지 브랜드 표기가 아니다.

## 4. 타이포그래피

**Figma: `Noto Sans KR`** (Regular · Medium · Bold — Semi Bold 없음). Inter는 한글 글리프가 없어 **절대 금지**. 실제 앱 서체는 신한 전용으로 추정되며 이 환경에 없다.
🔷 **React MVP 폰트**: Pretendard(웹폰트, 신한 서체와 시각적으로 가장 가까움) 제안. Figma와 MVP 서체가 달라지지만 스케일·굵기가 같으면 테스트에 영향 없음.

Figma 텍스트 스타일 13개 — **이미 전 화면에 적용돼 있으므로 최종 UI에서 건드리지 않는다.**

| 스타일 | 크기 / 굵기 | 어디에 |
|---|---|---|
| `display` | 28 Bold | 상품 상세 상품명 · 온보딩 헤드라인("아직 준비된 보험이 없어요") · 청구 제목 |
| `h1` | 24 Bold | 페이지 제목("금융" · "모든상품") |
| `h2` | 20 Bold | 섹션 제목 · 카드 제목 · 현황 카드 수치 · 팝업 제목 |
| `h3` | 18 Bold | 카드 소제목 · 묶음 제목("조회·계약") |
| `body-lg/bold` | 16 Bold | 버튼 글자 · 상품명 · 체크리스트 항목 강조 |
| `body-lg/medium` | 16 Medium | 상단 탭 · 리스트 항목 · 그리드 라벨(→ 14로 변경됨, §6) |
| `body-lg/regular` | 16 Regular | 본문 |
| `body/regular` | 15 Regular | 배너 문구 · 키-값 라벨 · 빈 상태 안내 |
| `body-sm/regular` | 14 Regular | 상품 설명 · 카드 본문 · 서브텍스트 |
| `body-sm/medium` | 14 Medium | 그리드 메뉴 라벨(8/18 변경) · 서류 박스 라벨 |
| `caption/regular` | 13 Regular | 부제 · 한계 문구 · "왜 보이는지" · 푸터 |
| `caption/medium` | 13 Medium | 텍스트 링크("기준 바꾸기") · 뱃지 |
| `label/medium` | 12 Medium | 하단 탭바 라벨 · 작은 뱃지 |

줄높이·자간은 스타일에 포함된 값 그대로. 새 크기 만들지 않는다 — 17·19·22 같은 중간값 금지.

## 7. 에셋 방침 (D-2) — 🔷 전부 팀장 결정

실제 앱의 아이콘·3D 일러스트는 **추출·복제하지 않는다** (저작권 + 기술적으로 불가). 대안:

| 에셋 | 제안 | 이유 |
|---|---|---|
| **UI 아이콘** (뒤로·검색·메뉴·홈·chevron·체크·탭바 5개·리스트 아이콘 12개) | 오픈 라이선스 라인 아이콘 세트 하나 (Lucide 또는 Phosphor, MIT) · 24px · stroke 1.5 · 색은 `text/disabled` 또는 primary | 세트 하나면 일관. 슈퍼SOL 아이콘과 "같지는 않지만 같은 결" |
| **서비스 아이콘** (보험계약조회·청구… 12개, 카테고리 9개) | 같은 라인 세트에서 의미 맞는 것. 없으면 첫 글자 원형 배지(`bg/tint` + 글자 primary) | 실제 앱은 컬러 일러스트 아이콘이지만 제작 불가 |
| **3D 일러스트** (보장에너지 배터리 · 추천 카드 · 팝업 문서) | **단순 도형 플레이스홀더 유지** — 원/사각 `bg/tint-alt` 위에 라인 아이콘 48 | 테스트 측정 대상이 아님. 어설픈 3D 대체물이 오히려 "딴 앱" 느낌을 만듦 |
| **로고** | 신한라이프·신한은행·신한카드 = 실제 로고 사용(자사 표기 방침) / 타사 = 가명 텍스트 뱃지 "A생명" | mock-data §0 |
| **카톡·푸시** | 실물 캡처 모사 — 카카오 노랑 `#FAE100` · iOS 알림 카드 흰 92% | 우리 토큰 밖이지만 플랫폼 표현이라 예외 |
| **상태바** | iOS 표준 (9:41 · 신호·와이파이·배터리) | 컴포넌트 `9:3` 그대로 |

## 8. 와이어프레임 → 최종 UI 전환 절차 (화면 1장 기준)

1. **`시안` 페이지에서 `최종 UI 디자인` 페이지(`5:4`)로 복제.** 원본은 남긴다(8/25 대조용).
2. **변수 모드 전환** — 프레임 선택 → 우측 패널 레이어 섹션 → `색상` 컬렉션 모드 **와이어프레임 → SOL**. 색이 바인딩된 요소는 전부 자동으로 바뀐다. 안 바뀌는 요소 = 변수 안 쓴 것 → 찾아서 변수 바인딩 (영준에게 요청 가능).
3. **텍스트 스타일 확인** — 이미 적용됨. 바꾸지 않는다.
4. **플레이스홀더 교체** — 아이콘 플레이스홀더 → §7 아이콘 / 이미지 플레이스홀더 → §7 일러스트 방침. 회색 박스가 남아 있으면 안 됨.
5. **회색조 전용 표현 정리** — 점선 슬롯 테두리 제거 · "1st 뷰포트 접힘선" 레이어 숨김 · 노트 프레임은 화면 밖 유지.
6. **상태 표현 색 적용** — §3 상태 색 규칙 (선택/부족·충분/토글).
7. **프레임 이름** — `[아이디어 N]` 태그 유지. "개선안" 글자 금지(8/25 전).
8. **검수 (§10)** → `03_final-ui/figma-links.md`에 노드 ID 기록.

화면 순서: 테스트 과제에 걸린 것부터 — S1(보험료 확인) → S4·S5(청구) → S3(보장) → S2(찾기) → S6.

## 9. 금지 목록

- ❌ 토큰에 없는 색 만들기 (연한 파랑 하나 더, 회색 하나 더…) — 없으면 가장 가까운 토큰을 쓰거나 영준에게 변수 추가 요청
- ❌ 그라데이션·그림자 임의 추가 — 그림자는 하단 탭바·푸시 배너·팝업 시트에만 (기존 패턴)
- ❌ r8 · 12 · 16 · 20 · 24 · pill 외 라운드
- ❌ Noto Sans KR 외 폰트. **Inter 절대 금지**
- ❌ 라이프 계열 색 `#265BF0` `#3668F6` `#111726` `#495365`
- ❌ 빨강·주황으로 "부족" 강조 — 가입 압박
- ❌ 실제 앱 아이콘·일러스트 추출
- ❌ 인스턴스 분리(detach)
- ❌ "개선안"·"솔루션"·팀명 글자 (8/25 전) · 회사 관점 문구("노출 증대")
