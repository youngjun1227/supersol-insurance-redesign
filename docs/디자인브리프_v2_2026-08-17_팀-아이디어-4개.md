## 0. 먼저 읽을 것
1. 아이디어 4개는 팀이 8/5 회의에서 정한 것. **4개 전부 시안을 그린다.** 최종은 8/25 종합 회의(가설 확정 + Gate 1).
2. 설문(8/15~19) 전이라 **모든 화면은 "가설 기반 시안"**. "개선안"은 8/25 이후 P에 연결된 것에만. 8/25에 지지되지 않은 아이디어 화면은 이미 그렸어도 뺀다 → 화면마다 아이디어 번호 태그.
3. 목표는 "예쁘게"가 아니라 9/11 테스트에서 기존 앱 vs MVP를 비교 측정할 수 있게. 룩앤필은 SuperSOL과 크게 다르지 않게.
4. 표현: "사용자는 ~를 불편해한다", "명백히", "확실히" 금지 → "~할 가능성", "가설: ~".
5. AI는 안을 여러 개 낸다. 고르는 것은 팀. 아이디어마다 2~3안.

## 1. 프로젝트
신한 SuperSOL 보험 화면 UX 개선. 대학생 4인 팀 SOL:VE, 신한라이프 현업 멘토. 주 대상 20대. 산출물 React 모바일웹 MVP(목데이터, 백엔드 없음, 화면 4~6개, 폰 브라우저 링크). 9/11~13 사용자 테스트(기존 앱 vs MVP, 1인 40~50분, 5~8명), 9/20 발표.
일정(참고) — 와이어프레임 8/15~19 → 최종 UI 8/20~24(Figma) → 🔒 8/25 17시 종합 회의 @신한라이프 → React MVP 8/25~31 → 9/1~ 다듬기·배포 → 🔒 9/11 테스트.

**현재 SuperSOL 보험 화면 — 팀 관찰 요약**
- 입구 3곳(금융 탭 > 보험 / 상품 탭 > 보험(가로 목록 우측 끝) / 사이드메뉴 > 보험), 라벨 셋 다 "보험", 도착 화면 다름, 상호 이동 안내 없음
- 상품 목록 [신한은행]/[신한라이프] 전환 탭(기본 신한은행). 은행 탭 = 타사만(상해·암·건강·치매·치아·여행자·대출상환·골프 7~8개), 라이프 탭 = 자사만(암·건강·치아·상해·연금저축 5개). 이름 4개 겹침, 상품 안 겹침, 구분 설명 없음. 은행 탭엔 회사명 없고 라이프 탭엔 줄마다 회사명. 목록 중간에 보장에너지 안내 삽입
- 금융 탭 "보험 추천 서비스" 12개 같은 크기, 우선순위 없음. 보험금청구가 그 안, 첫 화면 안 보임. 신청 배너 4개 흩어짐, 정보(건강사전·AI영양분석)와 거래 같은 자리
- 보장에너지: 보유 0건 계정에서 "보장금액이 하나도 없어요"만, 수치·기준 없음. "전문가에게 물어보세요"는 상담·가입으로
- 홈은 AI 개인화 표방하나 보험 화면은 계정 2개 모두 같은 구성

## 2. 팀이 정한 개선 아이디어 4개 (8/5)
| # | 아이디어 | 근거 상태 | 설문 |
|---|---|---|---|
| 1 | 상품 카테고리를 통일해 위로, 회사 탭은 아래로 | 강함 (관찰 8건 + 경쟁 2앱) | Q5·Q6 |
| 2 | 연령·보유상품 기반 맞춤 테마를 보험 탭에 | 외부 자료는 있음, 앱 관찰 약함 | Q3·Q4·Q7·Q12 |

### 아이디어 1 — 카테고리 통일해 위로, 회사 탭은 아래로
- 팀 결정: "보장"·"저축투자"처럼 양쪽 공통 카테고리로 통일해 상단에, [신한은행/신한라이프]는 그 아래로
- 가설: 판매 주체로 나뉘고 설명이 없어 위 탭을 지나치고 한쪽만 보고 나갈 가능성
- 그릴 것: 상품 찾기 목록(+ 카테고리 선택 후 목록). 2~3안 ① 카테고리 탭 상단 + 회사 필터 칩 ② 카테고리 상단 + 카드마다 판매사 뱃지(회사 탭 없음) ③ 토스식 상황 문장 카테고리. 구분 기준 한 줄 문구 후보(예: "은행에서 파는 다른 보험사 상품 / 신한라이프 상품")
- 경쟁: 모니모(첫 구분 금융상품 종류, 객관식 3문항 보험 찾기), 토스(상황 문장 → 가입 방식, 회사명은 카드 제목, 여러 사 한 목록)
- 쟁점: 효과는 사용자 관점만("찾는 상품에 더 빨리 닿는다"). "신한라이프 노출 증대" 금지(25% 룰). 카테고리 통일·탭 순서 조정 가능 여부 멘토 확인 대기

### 아이디어 2 — 연령·보유상품 기반 맞춤 테마
- 팀 결정: 홈 맞춤 테마를 보험 탭에도. 연령·보유 신한 상품 기준 5~6 테마 중 맞는 것 먼저. 20대 테마(연령 맞춤 추천 + 기존 가입 보험(부모 가입분 포함) 분석), 30대 테마(건강검진·암보험 상단)
- 가설: 20대는 보험을 잘 몰라 판단이 어렵고 부모가 들어준 보험이 뭔지 모를 가능성
- 그릴 것: 보험 메인 상단 맞춤 영역. MVP는 **"보유 0건 20대" · "보유 1~2건 20대(부모 가입분 포함)" 두 상태만**. 2안 ① 상단 맞춤 카드 1~2장 + 아래 공통 ② 토스식 상태별 화면 전체 분기. "왜 이것이 보이는지" 한 줄 + 기준 바꾸기/끄기 진입. "가족이 들어준 보험 한눈에" 카드(목록 + 보장 요약)
- 경쟁: 토스(계정 상태별 메인 다름), 모니모(홈 편집 반고정)
- 쟁점: 홈 "맞춤 테마 10가지"는 확인 안 됨(공식은 "AI 개인화 큐레이션 + 개인화 카드 약 50여 종") → "홈에 이미 있는 기능"이라 쓰지 않음. 데이터 우려(20대 36.1% 이용 망설임, 자사 중심 추천 불신, 선별 기준 공개 요구 69.8%) → 기준 명시·끄기 필수. Q12 "골라 보여주는 것 자체가 별로" 다수면 빠짐

### 아이디어 3 — 신한카드 결제 감지 → 보험금 청구 알림
- 팀 결정: 1안 카드 결제 감지 — 병원 신한카드 결제 시 카톡 "청구 서류 챙기세요" → 앱 진입 시 청구 페이지 바로 가는 팝업. 2안 위치 기반(1안 불가 시) — 병원 20분+ 머물다 벗어나면 팝업. 슈퍼앱(은행·카드·보험 한 지주)이라 가능하다는 차별점 논리
- 가설: 실손에서 병원 다녀온 뒤 서류를 못 챙겨 청구 시점을 놓칠 가능성
- 그릴 것 (카톡 알림 자체는 MVP 밖): ① 카톡 알림 메시지 시안 1장(정적) ② 앱 진입 팝업 "8/17 ○○병원 결제 32,000원, 청구하시겠어요?" + 서류 안내 + [청구하러 가기 / 나중에 / 이 알림 끄기] ③ 보험금 청구 화면 — 결제 내역 선택 방식 진입 + 절차 미리 안내(서류 준비 → 정보 입력 → 제출 → 결과). **아이디어 3이 빠져도 남는 화면** ④ "청구 알림 켜기" 동의 화면(opt-in). 2안 팝업은 ②의 문구 변형 1장
- 경쟁: 모니모(실손 청구를 카드 결제 내역 선택으로, 청구 입구 2탭·무스크롤, 절차 4단계 안내, 통합/실손24 두 갈래). **토스는 결제 감지 청구 알림을 이미 운영** → 차별점은 "같은 지주 신한카드 결제 직접 감지 + 알림→청구 한 흐름"
- 쟁점: 계열사 간 무동의 정보 이용은 "내부 경영관리" 한정·권유 아닌 업무 → 알림이 권유면 opt-in/마이데이터로만 → 동의 화면 필수. 2안은 위치정보법 동의. 미청구 이유는 조사마다 갈림(소액 90.6% vs 지급 불확실 41.4%·서류 26.3% vs 병원 방문시간 부족 46.6%) → 알림이 줄일 미청구는 일부일 가능성. 실손24 이용 낮음(140만 명, 연계 28.4%) → 앱 접점 여지. 관찰 0건이지만 **팀이 정한 아이디어라 그린다**, Q8·멘토 답은 8/25

### 아이디어 4 — 보장에너지에 구체 수치·정보
- 팀 결정: 같은 연령대 대비 보장 진단에 구체 수치·정보 제공
- 가설: 수치가 없어 판단 근거로 못 쓰고, "하나도 없어요 → 전문가" 가 권유로 읽혀 이탈 가능성
- 그릴 것: 진단 결과 화면 — ① 항목별(암·입원·실손·상해…) 부족/충분 수치 ② 비교 기준 문장("20대 중반과 비교했어요") ③ 한계 문구 ④ 상담·가입은 정보 뒤 + "권하는 것 아님" 명시. 2안 ① 수치 목록형 ② 그래프(오각형 등)+뱃지형. "하나도 없어요" 문구 대안 2~3개
- 경쟁: 토스(질문 0개 자동 리포트, 또래 비교 금액·부족 5개 뱃지·체크리스트·오각형·기준 문장·한계·"강요 안 함"·전문가 점검은 그 위 2겹), 모니모(부족 11개·또래 평균 6만원·별명, 단 분석이 상담으로, 또래 정의 없음)
- 쟁점: (가) 정보 제공 vs (나) 가입 유도 강화 — 방향 반대. **시안은 (가)로 그린다.** MZ 불만 1위 "최적 상품 제안했는지 의문" 60%. 비교 기준 데이터 멘토 확인. Q9 "부담" 다수면 약해짐

## 4. MVP 화면 구성 (4~6개)
| # | 화면 | 아이디어 | 테스트 과제 후보 |
|---|---|---|---|
| S1 | 보험 메인 — 맞춤 영역(2) · 핵심 행동(내 보험/청구/찾기) · 서비스 성격별 묶음 | 2 (+§3) | "이번 달 보험료 확인", "청구 화면까지 가기" |
| S2 | 상품 찾기 목록 — 공통 카테고리 상단, 회사는 필터/뱃지, 용어 툴팁 | 1 (+§3) | "○○ 보장 상품 찾아 비교하기" |
| S3 | 보장 진단 결과 — 항목별 수치·기준 문장·한계·상담은 뒤 | 4 | "내 보장이 충분한지 확인하기" |
| S4 | 청구 알림 팝업 → 보험금 청구 — 결제 건 선택·서류 안내·절차 | 3 (+§3) | 청구 과제 도착지 |
| S5 (선택) | 알림 켜기(동의) 화면 / 카톡 알림 시안 | 3 | 발표·설명용 |
| S6 (선택) | 상품 상세 1장 | §3 | Before 화면 확인 후 |
- 테스트 설계: 기존 앱 vs MVP 같은 구조·다른 시나리오. 지표 주력 **과제 성공률 / 클릭 수 / 어려웠나(7점)**, 보조 이해도·만족도, 시간은 참고만 → **시안은 클릭 수를 셀 수 있는 명확한 경로로**
- 목데이터: 실명·실번호 금지("김솔브", "010-0000-0000"). 상태 "보유 0건 20대" · "보유 1~2건 20대(부모 가입분 포함)"
- 8/25 전 우선순위(팀장 제안, 최종은 회의): 근거 두께 순 1 → 4 → 3 → 2로 잡되 **4개 모두 최소 1안**

## 5. 디자인 진행 시 지킬 것
- 화면마다 **아이디어 번호 태그**(프레임 이름/노트). 8/25 이후 P·SOL 번호로
- SuperSOL 룩앤필 유지. 구조 변화가 측정 대상
- 아이디어마다 2~3안. 팀이 고름. 이유는 회의 기록
- 경쟁 앱 참고만, 베끼지 않음. 참고 앱·화면을 노트에
- 노트에 단정 표현 금지. "가설: ~", "~할 가능성"
- 회사 관점 효과("노출 증대", "가입 전환") 금지 → 사용자 관점("더 빨리 닿는다", "판단 근거가 생긴다", "청구를 놓치지 않는다")
- 멘토 답변은 사실만 근거, 의견은 참고. 사용자 조사 우선
