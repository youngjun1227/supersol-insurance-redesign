## 2. 발표 순서와 각 장에서 할 말

### 2-1. 문제 제기 — "보험 탭에 들어가면 무슨 일이 벌어지나"
AS-IS 화면 3장(00 메인홈 → 01 금융›보험 → 07-1 청구 랜딩)을 띄우고 관찰을 말한다.

- 메인 홈에 **보험이 한 번도 안 나온다.** [금융] 탭 → 보험 세그먼트를 거쳐야 한다
- 보험 탭 첫 화면은 상담 배너 → 상품 광고 → 이벤트. **내 보험 얘기가 없다** (R-10 · O-105·O-201)
- 계약조회·청구는 **3스크롤 아래** "보험 추천 서비스" 12개 그리드 안에 있다 (R-02·R-03 · O-106·O-203)
- 보장에너지는 결과 대신 "알아볼까요?" 유도 문구만 (R-09 · O-404)

> 표현 규칙: "사용자는 불편해한다"가 아니라 **"~할 가능성이 있다"**. 전부 8/25 이전의 가설이다.

### 2-2. ① 찾게 한다 — 아이디어 1
**말할 것**
- 상품 목록이 **판매 주체**로 먼저 갈린다. [신한은행]엔 타사만 7~8개, [신한라이프]엔 자사만 5개. **이름은 4개 겹치는데 상품은 안 겹치고, 구분 설명이 없다** (O-102~104 · O-303)
- 그래서 위 탭을 지나치고 **한쪽만 보고 나갈 가능성**이 있다
- 시안: 보장 카테고리를 위로, 회사는 필터 칩/뱃지로 아래

**근거**
- 20대 이하 실손 미가입 1위 이유 **"상품을 잘 몰라서" 37.6%** (2023)
- 20대 **52.3%가 보장 내용을 모름** (2019)
- 경쟁: 모니모는 첫 구분이 금융상품 종류(C-304), 토스는 상황 문장 → 여러 사 한 목록(C-404)

**말하지 말 것:** "신한라이프 노출이 늘어난다" → **25% 룰**(보험업법 시행령 §40⑥)에 걸린다. 사용자 관점만.

### 2-3. ② 알게 한다 — 아이디어 4 + 2
**말할 것**
- 보장에너지 **진입 카드**가 결과 대신 "알아볼까요?" 유도만 하고(R-09), 0건 계정에서는 **"보장금액이 하나도 없어요"** → "전문가에게 물어보세요"로 상담·가입으로 간다 (O-404·O-405)
- ⚠️ **R-16 (8/19)**: 실물 결과 화면에 항목별 수치가 **이미 있다** (영준 실기기 확인). "기존엔 수치가 없다"고 말하면 틀림. 우리 차별점은 수치화가 아니라 ① 비교 기준 명시 ② 또래 대비 부족/충분 판정 ③ 한계 문구 ④ 상담 맨 뒤 + 비권유 ⑤ 0건 대안 문구 — **캡처 확보 후 실물에 이미 있는 항목은 뺀다**
- 시안: 문장 요약("또래보다 2,000만원 적게 준비돼 있어요") 또는 그래프 요약 + "20대 중반과 비교했어요" 기준 문장 + 한계 문구 + **"가입을 권하는 것이 아니에요"**
- 20대는 부모가 들어준 보험이 뭔지 모르는 경우가 있다 → **"가족이 들어준 보험 한눈에"** 카드

**근거**
- MZ 보험 가입 만족도 최저(3.3), **불만 1위 "최적 상품을 제안했는지 의문" 60%** (2021)
- 선별 기준 공개 요구 **69.8%**, 20대 **36.1%가 개인화 이용을 망설임** (KISDI 2025)
- 마이데이터 저해 요인 "자사 중심 추천" (하나금융 2022)
- 경쟁: 토스는 질문 0개 자동 리포트 + 또래 금액 + 한계 문구 + "강요 안 함"까지 얹는다 (C-402)

**말하는 순서 주의 (§4 함정 2)**
> ❌ "부모님 보험과 비교해 갈아타게 만듭니다"
> ✅ "부모님이 들어준 보험에 뭐가 있는지 **처음으로 알게 됩니다.** 판단은 사용자가 합니다 — 그 결과 옮기기도 합니다"

브리프 §2 아이디어 4에서 팀이 **(가) 정보 제공** 방향으로 이미 정했다. 발표 문장도 거기 맞춘다. 불만 1위가 "최적 제안 의문 60%"인데 우리가 밀어붙이면 그 불만을 그대로 재생산한다.

### 2-4. ③ 붙잡는다 — 아이디어 3 ★ 우리 하이라이트
**말할 것 (순서 그대로)**
1. **문제:** 실손 청구를 안 하는 이유는 "귀찮아서"가 아니다 → **병원 방문 시간 부족 46.6%**, 지급 불확실 41.4%, 서류가 유료·복잡 26.3% (금융위 2023 · 2019 조사)
2. **제도는 이미 있는데 안 쓴다:** 실손24 이용자 **140만 명**, 연계율 **28.4%** (2026-04) → 앱 접점의 여지
3. **그래서 시점이다:** 신한카드로 병원비를 결제한 **그 순간**, 카톡으로 "이 서류가 필요해요"를 보낸다 → 앱에 들어오면 팝업 → 청구 절차 안내 → 기존 청구 화면
4. **차별점:** 토스도 결제 감지 알림을 운영 중이다. 우리 차별점은 **같은 지주 안의 신한카드 결제를 직접 감지하고, 알림 → 청구가 한 흐름이라는 것**
5. **규제를 알고 설계했다:** 계열사 정보 이용은 권유 목적이면 막힌다(금융지주회사법 §48의2). 그래서 **이 알림은 권유가 아니라 안내**다 — opt-in 동의 화면(S5-A)을 먼저 두고, 문구도 "청구하세요"가 아니라 **"청구할 수 있어요"**로 썼다

**여기서 회사 관점을 말한다 (결과로)**
> "청구는 보험을 든 사람이 회사와 만나는 거의 유일한 순간입니다. 그 순간이 좋으면 그 보험사를 계속 쓸 이유가 생깁니다."

**말하지 말 것:** "이 알림으로 가입을 늘립니다" → 대상이 이미 가입자다. 그리고 그 말을 하는 순간 알림이 **권유**가 되어 5번 논리가 무너진다.

### 2-5. 검증 — "우리는 재봤다"
- 9/11~13 사용자 테스트, 기존 앱 vs MVP, 5~8명 × 40~50분
- 지표: **과제 성공률 · 클릭 수 · 어려웠나(7점)**. 보조로 이해도·만족도. **시간은 참고만**
- 과제 4개: 이번 달 보험료 확인 / 상품 찾아 비교 / 내 보장 충분한지 확인 / 청구 화면까지 가기
- Before/After 클릭 수 비교표를 여기서 보여준다

### 2-6. 한계 — 먼저 말한다
- 설문은 **행동 데이터가 아니라 예상·선호**다 (n≥10, 8/15~19)
- 표본이 작다 (테스트 5~8명)
- 아이디어 3은 **팀 관찰 0건**에서 출발했다. 외부·경쟁 자료로 세운 가설이다
- 규제 판단은 멘토 확인에 달려 있다 (§8-E)
- 수치는 전부 **가상 목데이터**다

## 4. 함정 3개 — 발표 전 반드시 확인

### 함정 1. "체류 시간을 늘린다"
우리가 만든 건 전부 **빨리 끝내주는** 것이다. 청구 입구를 무스크롤로 올리고, 클릭 2단계를 건너뛰고, 서류를 미리 알려준다. 지표도 클릭 수를 **줄이는** 쪽이다.
→ **"머무는 시간"이 아니라 "다시 올 이유"(방문 빈도)**로 말한다. 체류 시간을 말하면 "클릭 수를 줄였다면서요?"에 답할 수 없다.

### 함정 2. "갈아타게 만든다"
아이디어 4는 팀이 **(가) 정보 제공**으로 정했다. "옮기게 만든다"는 (나) 방향이고, MZ 불만 1위(최적 제안 의문 60%)를 재생산한다. 계열사 몰아주기(25% 룰)도 걸린다.
→ **"알게 된다 → 사용자가 판단한다 → 결과적으로 옮기기도 한다"** 순서로 말한다.

### 함정 3. "20대는 복잡한 걸 싫어하니까"
근거를 물으면 막히는 세대 일반화다. 우리에겐 더 센 숫자가 있다.
→ **"미청구 이유 1위가 병원 방문 시간 부족 46.6%"** + **"실손24 연계율 28.4%"**. 조사 결과와 우리 화면이 1:1로 붙는다: *"우리 알림은 바로 그 시점에, 바로 그 서류를 말해줍니다."*

## 5. 예상 질문과 답

| 질문 | 답 |
|---|---|
| "이 청구 알림이 어떻게 가입을 늘리죠?" | 늘리지 않습니다. 이미 가입한 고객이 떠나지 않게 하는 장치입니다. 가입은 ①·②가 맡습니다 |
| "계열사 정보를 그렇게 써도 되나요?" | 권유 목적이면 안 됩니다. 그래서 opt-in 동의를 먼저 받고 문구를 안내 수준으로 낮췄습니다. 최종 판단은 멘토 확인 대기 중입니다 |
| "토스에 이미 있지 않나요?" | 있습니다. 차이는 같은 지주 안의 카드 결제를 직접 감지한다는 것, 그리고 알림에서 청구까지 한 흐름이라는 것입니다 |
| "왜 청구 화면 자체는 안 고쳤나요?" | 약관·심사 요건이 얽혀 있어 우리가 판단할 근거가 없습니다. 범위를 감지와 진입까지로 정했습니다 |
| "카드 결제 내역으로 청구하면 더 편하지 않나요?" | 카드 금액과 청구 대상 금액이 다를 수 있어 오히려 틀린 값을 채웁니다. 영수증은 어차피 내야 합니다 |
| "표본이 너무 적지 않나요?" | 적습니다. 방향을 보는 정성 테스트이고, 수치는 참고값이라고 먼저 말씀드립니다 |
| "위치 기반은 왜 뺐나요?" | 도심은 한 건물에 병원이 여러 곳이라 위치로 특정할 수 없습니다. 오탐이 잦은 알림은 켜둘 이유가 없습니다 |
