# 발견 기록: 보험 영역 내 디자인 시스템 2계열 혼재 → SOL 계열로 통일 결정

- 일자: 2026-08-17
- 단계: 1단계 AS-IS (토큰 추출 중)
- 결정자: 영준
- 상태: ✅ 결정 완료

## 1. 발견 내용
슈퍼SOL 앱 보험 영역(범위 A+B) 캡처 16장의 픽셀을 분석한 결과, 화면 제공 주체에 따라 **서로 다른 두 디자인 토큰 세트**가 쓰이고 있음.

| 항목 | SOL 계열 (슈퍼SOL 본체) | 신한라이프 계열 (신한라이프 제공 화면) |
|---|---|---|
| 해당 화면 | 01 금융›보험 홈(틀), 02 상품›신한은행, 03 상품›신한라이프(목록), 06 타사 상품 상세 | 04 보험상품 목록(암.건강), 05 신한라이프 상품 상세, 01의 일부 추천 카드 |

| 텍스트 본문 | `#344054` | `#495365` |

| 상품 상세 레이아웃 | 스탯 3열 + 버튼 2개 + 탭 (06) | 히어로 + 카드 캐러셀 + 하단 고정 CTA (05) |

### 왜 이런가 (추정)
- 금융›보험 홈과 신한라이프 상품 상세는 **신한라이프가 제공하는 화면**(푸터에 "신한라이프에서 제공하는 화면입니다" 명시)이고, 나머지는 슈퍼SOL(신한은행) 네이티브 화면.
- 두 회사의 디자인 시스템이 앱 안에서 그대로 병치되면서, 사용자 입장에서는 같은 "보험" 안에서 버튼 모양·색·상세 화면 구조가 바뀌는 경험을 하게 됨.

### UX 관점 의미
- **일관성 문제(P-xx 후보):** 자사(05) / 타사(06) 상품 상세가 완전히 다른 레이아웃·CTA를 가짐. 상품 비교 흐름에서 인지 부하 증가.
- **브랜드 인식 문제:** 색·라운드가 미묘하게 달라 "다른 앱으로 넘어간 것 같은" 느낌.
- 이 문제는 재배치/구조 개선만으로는 해결되지 않고, **토큰 기준을 하나로 정하는 것**이 선행돼야 함.

## 2. 결정
**리디자인 기준 팔레트 = SOL 계열로 통일.**

근거:
1. 슈퍼SOL 앱의 본체 스타일이며, 보험 외 다른 탭(은행·카드·증권 등)과도 일관됨.
2. 프로젝트 원칙("기존 슈퍼쏠 컴포넌트 스타일 유지")에서 "기존 슈퍼쏠"은 앱 본체를 의미하는 것이 자연스러움.
3. 신한라이프 계열 화면이 SOL 스타일로 바뀌는 것 자체가 개선안(TO-BE)의 근거가 됨.

## 3. 적용 방식
- `00_reference/design-tokens/tokens.md`의 기준값은 SOL 계열. 신한라이프 값은 "참고"로만 병기.
- Figma `디자인 토큰` 페이지 Variables는 SOL 계열만 등록.
- 1단계 AS-IS 와이어프레임은 **현재 상태를 그대로** 기록(두 계열 차이가 보이도록 주석 표기). 회색조라 색은 안 드러나지만 버튼 높이·라운드·레이아웃 차이는 그대로 재현.
- 2단계 TO-BE에서 04·05 화면을 SOL 토큰(버튼 h48·r8, 텍스트 `#101828` 계열)으로 통일.
- `02_to-be/problems.md`에 이 발견을 P-01(가칭 "자사/타사 화면 디자인 시스템 불일치")로 등록.
